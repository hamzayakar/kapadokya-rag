# Agentic RAG Pipeline & Chunking Strategy Benchmark

An advanced, research-oriented Retrieval-Augmented Generation (RAG) system built to analyze, retrieve, and evaluate official regulations, directives, and external legal references for Kapadokya University.

## 🎯 Project Overview & Thesis Objective

This project serves as both a functional **Agentic RAG application** and an **academic testing arena**. It is designed to solve the "context fragmentation" and "semantic illusion" problems in legal documents by comparing traditional chunking methods against advanced, LLM-driven (Native Gemini) chunking strategies with **Deterministic Citation Resolution**. 

By eliminating opaque orchestrators (like LangChain's Agent abstraction) in the core runtime, this project utilizes **Native Google Generative AI SDK** to achieve deterministic tool calling, zero-overhead routing, and exact observability.

## 🧠 Architecture & Key Features

### 1. Multi-Strategy Ingestion & Citation Resolution
The system evaluates 5 distinct chunking strategies side-by-side using isolated Qdrant vector collections:
- **Gemini Mega-Chunking:** LLM-driven chunking that preserves entire sequential rules and logical execution orders.
- **Gemini Parent-Child:** Hierarchical chunking that links overarching summaries to exact sub-clauses.
- **Baseline Naive:** Langchain's `RecursiveCharacterTextSplitter`.
- **Baseline Semantic:** Langchain's `SemanticChunker`.
- **Baseline Unstructured:** Layout-aware parsing using `unstructured[pdf]`.

**✨ Novel Intermediate Step (The Citation Linker):** During agentic extraction, explicit citations are caught as `raw_references`. A secondary Gemini Flash 2.5 agent acts as a Linker, scanning the local directory to resolve these fuzzy citations into exact PDF filenames (e.g., `2547_sayili_kanun.pdf`), enabling strict SQL-like metadata filtering instead of error-prone semantic guessing.

### 2. Native Agentic Retrieval & Tool Calling
Instead of relying on single-shot retrieval, the agent dynamically decides when to fetch more context:
- `document_searcher`: Performs semantic search strictly within a targeted source document if a chunk feels cut off.
- `hierarchy_fetcher`: Retrieves the entire family of sub-clauses for a specific parent article.
- `reference_fetcher`: Automatically traverses cross-references using the strictly resolved filenames from the Linker step, executing a targeted hybrid search.

### 3. Synthetic QA Generation & LLM-as-a-Judge Benchmarking
- **Generator Agent:** Automatically reads the resolved JSON chunks and uses the `reference_fetcher` tool to create "Hard", multi-hop, cross-document questions.
- **Evaluator Agent:** A Gemini 2.5 Pro judge runs these questions against all 5 Qdrant collections, scoring the RAG answers from 0-5 based on hallucination, completeness, and accuracy, outputting a final `.csv` report.

### 4. Smart Routing & Advanced Observability (Langfuse)
- **Router (Gemini Flash):** Intercepts queries to classify intent. Casual chit-chat bypasses the vector database entirely, returning immediate responses.
- **Zero-Downtime Prompt Management:** System prompts and model configurations are injected dynamically via Langfuse, requiring no redeployments.
- **Intelligent Session Management:** Unique Session IDs are generated by hashing the `Browser Context + UI Tab + First Message`, ensuring that evaluations and traces are cleanly separated by chunking strategy and user intent.

## 📂 Directory Structure

- `data/`: Local volume for raw PDFs, processed JSON chunks, and evaluation datasets.
- `research/`: Synthetic data generator and LLM-as-a-Judge benchmarking scripts.
- `src/config/`: Dynamic settings and baseline prompt definitions.
- `src/ingestion/`: The CLI engine for PDF extraction, chunking, and Qdrant upsertion.
- `src/rag/`: Core LLM logic, Native SDK agent, and Qdrant retriever.
- `src/tools/`: Deterministic functions exposed to the Gemini Agent.
- `app.py`: Stateless Gradio UI serving 5 independent benchmarking tabs.

## 🚀 Ingestion Pipeline Usage (Local CLI)

The project includes an enterprise-grade Command Line Interface (`cli.py`) to handle the entire data pipeline from raw PDFs to Qdrant vector collections. It features built-in collision control to prevent accidental data duplication.

### CLI Arguments Reference
| Argument | Description | Available Options |
| :--- | :--- | :--- |
| `--action` | **(Required)** The pipeline stage to execute. | `extract`, `push`, `delete` |
| `--method` | **(Required)** The chunking engine to use. | `gemini`, `langchain`, `unstructured` |
| `--strategy` | Specific algorithmic strategy for the chosen engine. | `mega`, `parent_child`, `naive`, `semantic`, `layout` |
| `--folder` | Target data directory inside `data/raw_docs/`. | `kapadokya`, `external` (Default: kapadokya) |
| `--file` | *(Optional)* Target a single specific document instead of the whole folder. | e.g., `yonetmelik.pdf` |
| `--force` | *(Optional)* Bypass collision safety. Overwrites existing JSONs or deletes existing vectors before pushing. | Flag (no value needed) |

---

### Phase 1: Extract (PDF to JSON)
Extracts text from raw PDFs based on the chosen methodology and saves structured JSON chunks into `data/processed_chunks/`.

**Example 1: Gemini LLM Chunking (Agentic Approach)**
```bash
# Extract using Mega-Chunking strategy
python -m src.ingestion.cli --action extract --method gemini --strategy mega

# Extract using Parent-Child hierarchy strategy
python -m src.ingestion.cli --action extract --method gemini --strategy parent_child
```

**Example 2: Baseline Chunking (Traditional Approach)**
```bash
# Extract using Langchain's Naive character splitter
python -m src.ingestion.cli --action extract --method langchain --strategy naive

# Extract using Langchain's Semantic chunker
python -m src.ingestion.cli --action extract --method langchain --strategy semantic

# Extract using Unstructured layout parser
python -m src.ingestion.cli --action extract --method unstructured --strategy layout
```

**Example 3: Targeted Single File Extraction with Force Override**
If you updated a specific PDF and want to overwrite its existing chunks:
```bash
python -m src.ingestion.cli --action extract --method gemini --strategy mega --file "YNG.001.BOLOGNA.pdf" --force
```

---

### Phase 2: Push (JSON to Qdrant Vector DB)
Embeds the extracted JSON chunks using `gemini-embedding-001` and upserts them into isolated Qdrant collections (e.g., `kapadokya_gemini_mega`).

**Pushing an entire folder:**
*(Automatically skips files that are already indexed unless `--force` is provided).*
```bash
python -m src.ingestion.cli --action push --method gemini --strategy mega --folder kapadokya
```

**Pushing a single specific file:**
```bash
python -m src.ingestion.cli --action push --method langchain --strategy naive --folder kapadokya --file "YNG.001.BOLOGNA_chunks.json"
```

---

### Phase 3: Clean Up / Delete Vectors
Safely purges all vectors associated with a specific document source from the target collection without dropping the entire database.

```bash
# Deletes 'yonetmelik.pdf' vectors from the 'kapadokya_baseline_naive' collection
python -m src.ingestion.cli --action delete --method langchain --strategy naive --folder kapadokya --file yonetmelik.pdf
```
